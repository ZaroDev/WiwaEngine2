# Animation

Code: `engine/src/animation` (poses, nodes, `AnimatorInstance`, `AnimationModule`), `engine/src/scripting/bindings/bind_animation.cpp`, the skinning parts of `engine/src/renderer`, `editor/src/animation` (panel), `tests/src/animation` (smoke tests), `editor/src/asset_editor` (clip editor), importers in `editor/src/asset_pipeline/importers/model_skeleton.*`. User API: `docs/scripting.md`. Verified by `--anim-smoke`, `--anim-panel-smoke`, `--render-test` (`skinning_checks.cpp`) and the animated warrior in `--demo-smoke`.

Part 1 of 5 (foundation), with the native animation assets (B1) on top of it. Part 2, stage one (state-machine animation graphs) is in too, see "Animation graph" below. Later parts are the general pose graph (a state body that is a node graph), root motion, IK and ragdoll; this area only keeps them possible (see the end).

## Assets

- **Native files.** Skeletons, clips and skinned meshes are files the user owns: `.wskel` (JSON), `.wanim` and `.wmesh` (binary, magic `WANM`/`WMSH` + version; read and written by `engine/src/assets/native_anim_files.*`, the one description of the formats, so the editors write what the importers read). The importers (`importers/native_anim_importers.cpp`) cook them into the `Skeleton`, `AnimationClip` and `Mesh` asset types. The model importer **extracts** them once (below).
- `SkeletonData`: `JointNames` (unique), `InverseBind`, `Parents` (joint index, -1 for a root; **a parent always comes before its children**), `RestTranslation/Rotation/Scale` (the joint's own node) and `Pre` (the nodes between the joint and its parent joint, or above a root joint: an Armature node scaled 0.01 and turned -90 degrees, for one). A joint's matrix is `parent * Pre * local`, so clips, which animate the joint's own TRS only, never lose what is folded into `Pre`, and poses are in the space of the model root (the entity with the `Animator`). The model importer fills them (`finalize_model_skeletons`, on `ImportedSkeleton`, which keeps the node of each joint): it sorts the joints parent first, makes joint names unique (`_2`) and **remaps the joint indices of every mesh vertex** it skins. More than 256 joints is a warning (the palette cap). A skinned mesh names joints by their place in its skeleton, so a mesh is driven by the Animator whose `Skeleton` is the same asset; `MeshData::Skeleton` and `SkinJointNames` record which, and the `.wmesh` importer cooks the mesh unskinned (draws rigid) when the skeleton's joint names are not the recorded ones.
- `AnimationClipData`: channels keyed by **joint name** (`AnimationChannel::Joint`), the `Skeleton` it was made for, plus `Events` (`{time, name}`, sorted). Events live in the `.wanim`; the clip editor of the Asset Editor reads and writes them there (atomic temp + rename, the rest of the file kept), and the importer re-cooks the clip. The model's legacy `animationEvents` import setting only **seeds** a clip the first time it is extracted. **`.meta` files are git-ignored in this repo**, so the extracted files' `.meta` (and the models') must be force-added; the demo hall's models carry the pre-assigned GUIDs and legacy sub-asset ids the scene points at (`scripts/gen_demo_scene.py`).
- `WASSET_VERSION` is 4: an older `.wpak` fails to load cleanly and has to be packed again. The import cache entry stores `wassetVersion`, so a bump re-cooks everything (the importer version alone would not). The editor cooks the engine's own assets (`AssetDatabase::cook_root`, called from the `Editor` constructor) **before** the engine starts, so a cold Library (first run, or after a bump) does not leave the renderer without shaders.
- A **ClipBinding** (`bind_clip`) maps each channel to a joint by name; a channel whose joint the skeleton lacks is left out with one warning per (clip, skeleton). `clip_compatibility` says Full, Partial (with the missing names) or None; a clip plays on any skeleton that has its joints (no retargeting), and a None clip logs once and moves nothing.
- **Extraction** (`importers/model_extract.*`): importing a model writes `<Model>_animation/` (`<skeleton>.wskel`, `clips/*.wanim`, `meshes/*.wmesh`, skinned meshes only; static meshes stay sub-assets) **once** and never overwrites or deletes a file. The model's `.meta` setting `extracted` records per item `{legacy, guid, file}`: a renamed or moved file is found again by its guid, a deleted one is written again where it was, a new clip in the FBX gets a new file, a changed source clip changes nothing. If a file cannot be written the model import fails with the reason. Physics shapes are not generated for skinned meshes. The legacy sub-asset ids (`skeleton/N`, `animation/N`, skinned `mesh/N`) stay reserved in the `.meta` and are no longer cooked: `ImportContext::add_redirect` records legacy -> extracted, the database keeps the pairs in the import cache, `catalog.wcat` carries them (`AssetCatalog::Redirects`), and `AssetManager` follows them (one step) so old scenes and prefabs keep loading. The packer follows them too and the pak catalog keeps them. File > *Update references to extracted assets...* rewrites scenes, prefabs and UI panels to the new guids after a dry run (optional). An importer that names another asset by guid finds its file on a cold Library because `AssetDatabase::index_meta_guids` reads every `.meta` before importing.

- **Sockets (skeleton).** `SkeletonData::Sockets`: `{ name, joint (name), position, rotation, scale }`, names unique, each on a joint of the skeleton. `.wskel` version 2 carries `"sockets"` (version 1 files still read, with none); the cooked Skeleton has them (`WASSET_VERSION` 4). They are authored in the Asset Editor. Nothing in the runtime reads them yet (the `AnimationSocket` component still names a joint); a lookup by socket name is for the Lua/graph part.
- **Import: vertex space and attachments** (`importers/model_import_fbx.cpp`, `model_skeleton.cpp`; importer version 9). **A skinned mesh's vertices are in model space (the bind pose), as in glTF.** The FBX reader moves them by `bind_to_world * geometry_to_bone` (equal for every cluster of a mesh; a Blender character is Z up and its mesh node turns it, which only the joints used to see, so a skinned mesh drawn without a palette lay on its back) and stores `inverse(bind_to_world)` as the inverse bind: the skinned result is unchanged. **A rigid mesh node below a joint** (sword, pads, face, a hat) is moved only by the Animator's sockets, so the prefab gives it an `AnimationSocket` on its nearest joint (`add_attachment_sockets`: offset = rest pose between the joint and the node, scale included; a rigid mesh below another one follows its parent). Sockets are written in Play only (not for previews, see above), so in the editor view and previews attachments stand at their rest place. Changing the vertex space means the extracted `.wskel` and `.wmesh` of a model must be written again together (delete both, keep their `.meta`: the import writes them again under the same guids); `.wanim` clips are joint-local and stay.
- **Preview scenes.** `AnimationModule::register_preview_scene` makes every enabled Animator of a scene (an Asset Editor preview, the thumbnail scene) get a preview instance that advances with **real** time, whatever the game clock does; `instance_in(scene, entity)` finds it and the render module takes the palettes of an offscreen view from it. They hold the scene weakly, write no sockets and queue no events. The `ViewHost` scenes of the game UI are registered too, so a model with a clip on its prefab Animator plays in its portrait (the demo's prefab has none: the portrait stands in the bind pose). The mesh entity of such a scene is the Animator and the skinned mesh at once and needs a `SkinBinding` (`make_preview_entity`).

## Components

`Animator` (`Skeleton`, `Clips`, `Clip`, `PlayOnStart`, `Speed`, `Enabled`, `BoundsPadding`, `Graph`), `AnimationSocket` (`Joint`, `OffsetPosition`, `OffsetRotation`, `OffsetScale`), `SkinBinding` (`Skeleton`). All reflected. The prefab expander adds `Animator` to the root of an instance of a model with animations (unless the scene already has one) and `SkinBinding` to every skinned node. `Animator.Graph` (an `AnimationGraph` asset) plays instead of `Clip` (below).

Runtime state is not a component: `AnimationModule` (priority 10, after the scripts) keeps an `AnimatorInstance` per Animator **of the scene it last saw** (another scene object, such as the play-mode clone, starts with none; an asset reload drops them all). Instances exist while the game clock plays, and as editor previews. `AnimationModule::tick(scene, dt, playing)` is the testable seam; `update()` calls it. Scripts run before it, so `acquire()` makes an instance on demand for them.

## Evaluation

`Pose` = local TRS per joint. Nodes (`pose_nodes.h`): `ClipNode` (time, loop/once, per-channel key cursor, events), `BlendNode` (lerp/nlerp along the shortest path, optional ramp), `AdditiveNode` (clip minus its first frame), `MaskNode` (per-joint weights), `RestNode`. `advance(dt, weight, events)` moves state and emits events; `evaluate(pose)` is a function of the node's own state. An event fires only for a clip whose effective weight is above 0.5, so the two sides of a crossfade do not both fire a footstep.

`AnimatorInstance`: `play` replaces the root, `crossfade` wraps it as `Blend(old, new)` and ramps, `stop` fades to `RestNode`; a finished blend collapses to its child, and a crossfade started with 24 nodes or more settles the older fades first, so the tree stays bounded. Layers (`add_layer`) are kept beside the base: masked (override) or additive (one clip). A command that needs a clip that has not loaded waits, in order, and runs the frame it can; a name that is unknown once every clip has loaded is logged and dropped.

Palette = `model[j] * inverseBind[j]`, three float4 rows per joint (`JointMatrix`). Sockets are written after evaluation (`AnimationSocket`'s `Transform` from the joint, relative to its parent); **not for previews**, which never write the scene.

## Animation graph

Design: `docs/superpowers/specs/2026-11-08-animation-graph-design.md`. An `AnimationGraphData` (`.wgraph`, asset type `AnimationGraph`, `WASSET_VERSION` 5) holds parameters (`float`, `int`, `bool`, `trigger`), and layers that each hold a state machine. **The JSON file (`native_anim_files.*`: `write_graph_file`, `read_graph_file`, `graph_valid`) is the one description of the format**; the cooked asset is a version and that text. `graph_valid` is what the importer (`GraphFileImporter`, a failed import keeps the old cooked graph) and Save enforce: unique non-empty names (at most 64 characters), a first layer that is the base layer and no other, a default state, transitions and conditions that name what exists with an operator that fits the parameter's kind, blend axes, speeds and layer weights that name float parameters, a clip for every state and sample, finite numbers, exit time in 0..1. `read_graph_file(text, error, false)` reads without it: the editor opens a graph that is being made.

- **A state** plays a clip or a **blend space** (1D or 2D over float parameters; samples with x, y), with a speed (a constant times an optional float parameter) and a loop flag. A layer is a **base** layer, an **override** layer (a mask: a root joint and its subtree, the weight dropping by a falloff per joint of depth, or a joint list; `MaskNode`) or an **additive** layer (the change of each state from its first frame; `AdditiveMachineNode`), with a constant weight or one driven by a float parameter.
- **Transitions** (`StateMachineNode`): conditions on parameters (all must hold; `> < >= <= == !=` for floats and ints, true/false for bools, `fired` for triggers), a crossfade duration (0: instant) and an optional exit time (a fraction of the source state's length). Each advance moves the active state (and the one fading out), then looks at the transitions: **those from the active state first, then those from "any state", each in file order; the first whose conditions hold fires**. A transition to the active state is ignored. The entered state starts at its first frame. A transition that fires **during a fade freezes the pose as it is and fades from that**, so the pose never jumps. The triggers a fired transition used are consumed; triggers nobody used are cleared at the end of the frame (`GraphParams::end_frame`). Events keep the 0.5 rule: the active state gets the fade weight, the outgoing one the rest. A clip that plays once holds its last pose.
- **Blend space** (`BlendSpaceNode`): one shared phase drives every sample (so steps stay together), each clip fires its own events under the 0.5 rule. 1D clamps to the samples' range and blends the two around the value (the first of samples that share an x); 2D uses **gradient bands** (no triangles, so nothing jumps where triangles would meet): a sample weighs the least, over the other samples, of 1 minus how far the point has moved from this sample toward that one as a share of their distance (never below 0), and the weights are made to sum to 1; it is exact on a sample, handles samples on a line and points outside them (a sample at the same place as an earlier one gets 0).
- **Runtime** (`AnimatorInstance`, `graph_compiler.*`): once the skeleton, the graph and its clips have loaded, `compile_graph` turns the layers into the nodes above (a clip that has not loaded makes the whole graph wait, nothing is half built) and the result becomes the instance's root (**graph layers compose into the root; the script layers of `add_layer` still stack above it**). No `collapse()` in graph mode (a layer at weight 0 must stay: its weight follows a parameter). A graph for another skeleton (judged by identical joint names, not by reference: a legacy and an extracted skeleton reference are one rig) or an invalid one is logged once and the Animator plays its `Clip` instead. A graph or clip that never loads waits for ever (rest pose). `play`, `crossfade` and `stop` leave graph mode for good (also when called before it compiled). Parameter writes before it compiled are queued (64 at most) and applied, and checked, then; a refused write (unknown name, a trigger set as a value, a value for a trigger, not a number) is logged once per name and ignored. Parameters reset when an instance is made (Play, a reload).
- **Lua** (`bind_animation.cpp`): `anim:set(name, number|bool)`, `anim:get(name)`, `anim:trigger(name)`, `anim:state(layer)`; see docs/scripting.md.
- **Editor**: the Graph editor of the Asset Editor (editor.md). The preview plays the **saved** graph.
- **Traps**: the vendored `GraphEditor` widget gives a slot one link and a state has many transitions, so every canvas node has one slot per link and a spare (`GraphCanvas`); picking a link up deletes the transition. A state with no clip is allowed in the editor (a new graph has one) and refused by the importer, so **New animation graph logs one import error until a clip is assigned**.

## Skinning and rendering

- A mesh keeps `SkinVertices` (four joints and weights) in a **per-page skin buffer** parallel to the page's vertex buffer, created when the first skinned mesh lands on the page, uploaded with the mesh. Rigid meshes cost nothing.
- Palettes travel main to render in the same `SceneExtractor::extract` as the world matrix (`SceneDelta::PaletteUpdates`, sent when a pose differs from what was sent; an empty one makes the instance rigid again). `RenderScene` keeps `PrevPalette` and rolls it in `end_frame`, like `PrevWorld`: the render thread keeps the previous one, not main. The Animator of a skinned mesh is found by skeleton through `AssetManager::resolve` (a legacy sub-asset reference in an older scene and the extracted `.wskel` are one skeleton; a plain `==` left such a body unskinned, drawn rigid at its node). A skinned instance's world matrix is the **Animator's**, not the mesh node's, and its culling bounds grow by `Animator::BoundsPadding`.
- `GpuInstance` has a `Skin` row (palette rows now and before; `NO_PALETTE` = rigid). Vertex shaders skin before the world matrix with `SkinPoint`/`SkinNormal` (`scene_common.hlsli`); `PreviousClipPosition` skins with the previous palette. A user surface shader's `VertexOffset` applies before skinning. Non-uniform joint scale is not supported (normals use the upper 3x3). A palette shorter than the mesh's joint count is ignored (drawn rigid) so the shader never reads past it.
- **Edit mode:** a skinned mesh with no palette is drawn unskinned at the Animator's world. That is the bind pose, which equals the rest pose of the nodes only when the inverse-bind matrices match them (a rig bound in an A pose with a T-pose node rest shows the T pose in edit mode and pops to the A pose when Play starts).

## Traps

- **The skin data cannot live in the frame set.** Its registers span 1..9 and the material layout sits in t10..t13 (D3D12 wants each layout's range to be contiguous), and Vulkan's binding 0 is already `b0`. Palettes (`t22`) and skin vertices (`t23`) are their own **skin set, always the last set** of every pass that draws meshes; each mesh shader defines `SKIN_SET` (its number on Vulkan: the count of layouts before it) before including `scene_common.hlsli`. A new pass that draws meshes must append `data.skin_layout()` to its layouts (`scene_pass::draw_items` binds the set).
- **`SV_VertexID` differs by API:** Vulkan includes the base vertex, D3D does not. The base vertex is the third push constant of a mesh draw (`DrawConstants.BaseVertex`, 12 bytes) and `SkinVertexIndex` adds it on D3D.
- `BlendNode::collapse` keeps a blend that is ramping at weight 0: a frame of no time (Speed 0, a paused game) must not free the clip that was just started (`m_Current` points at it).
- Shutdown order: the new handles in `SceneRenderData::shutdown` must be reset before the device goes (Vulkan and D3D12 crash otherwise).
- `ScriptingModule` reads the animation module when it starts, so `Engine` registers `AnimationModule` before it.
- Events reach scripts one frame late, like UI events; `joint_world` reads the previous evaluation.

## Editor

`AnimationPanel`: for the selected entity with an `Animator`, a preview of a clip in the viewport (the module's preview instance: play, pause, scrub, speed, loop; ends when the selection changes or the game plays, see `preview_continues`) and no editing of its own: clips and their events are edited in the clip editor (editor.md, Asset Editor), through `ClipEditModel`. The inspector shows the socket joint as a drop-down of the skeleton's joints. "Show skeleton" draws the joints with `DebugDraw`.
