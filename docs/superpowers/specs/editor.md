# Editor

Code: `editor/src` (`editor_module.cpp` wires the panels, menus and smoke flags). The editor is a separate project over the engine lib; the game never links it.

## Panels (`editor/src/panels`)

Hierarchy, Inspector, World, Physics, Input, Viewport, Game, Performance, Console (level toggles with counts), Material, Asset Browser, UI Editor, History. Build Settings is a popup, not a panel. Panels draw from their own `on_draw()` with `ImGui::` and have a `PanelCategory` (Window / Info / Renderer menus in `editor_module.cpp`).

- **Hierarchy:** entity tree, reparent by drag, a Create menu (header button, background and entity context menus) built from `EntityTemplates`, a search box (names, and component names with the "Components" box), component icons per row, Ctrl+D / F2 / Ctrl+C / Ctrl+X / Ctrl+V / F (and double-click) focus, a prefab picker. Drop a Prefab or model asset on a row or the empty space for an instance, a Material on a row with a `MeshRenderer` to assign it. Scene operations are in the File menu.
- **Inspector:** one widget per `FieldType` from the reflection descriptors; override markers and revert on prefab children. Asset slots (`draw_asset_slot`, `asset_field.*`) show the type icon and file name of the asset, a tooltip with path, guid, sub-asset id and type, a red "(missing)" state when the catalog has no such guid, a right-click menu (Show in browser, Find references, Copy guid, Clear) and a Clear button; the expected type is shown on an empty slot. A wrong-type drop is not rejected (the catalog has no type for a guid and a model fills Mesh, Skeleton, AnimationClip and Prefab slots). Entity fields show the target's name. Three consecutive Bool fields named `<P>X`, `<P>Y`, `<P>Z` (RigidBody `LockPosition*`, `LockRotation*`) draw as one row like a vector (a presentation rule of the Inspector, not a field type). Component headers have a close button (remove), and a menu with Reset to defaults, Copy and Paste values; any field resets from its right-click menu; the Add component popup has a search box; a Lock button keeps the Inspector on one entity. Dragging or typing in a widget is one undo step (`SceneEditor::begin_edit_scope`).
- **World** (one searchable panel; the old per-effect panels are gone): sections Environment, Lighting, Exposure, Tonemap, Bloom, Ambient occlusion, Temporal AA, Motion blur, Scripts edit the active scene's `SceneSettings` (marks the scene dirty, saved with Save); `RenderQuality` (global, `render_quality.json`, not the scene) is edited in the Settings panel, Renderer page, not here. The Settings panel holds every project-wide value (project-settings.md); the Physics layers, the default input map and the Viewport gizmo settings are edited there too. A search that matches nothing shows "No settings match". Add new effects as sections here.
- **Asset Browser:** create menu with naming-first popup and templates (`asset_templates.*`: name validation rejects path separators, trailing dots, reserved names such as `CON`), drop targets (an entity dragged in becomes a prefab), "Always include in build" context item.
- **Game:** the scene through its primary camera with no debug draw, gizmos, outline or picking (Unity's Game view); the game is played in it. It shares the renderer's one view with the Viewport (the renderer draws one view per frame and its passes keep per-view state): `ViewOwner` records the frame the Game panel was drawn visible, and the Viewport gives way (a note, no camera, selection or input) while that stamp is this frame's or the last one's. Docked as tabs only the visible tab renders; side by side the Game panel wins. While it owns the render it sets: primary camera (`set_camera_override(nullopt)`, UI override cleared), `DebugDraw::set_enabled(false)`, no selection. `PlayInputRouter` (shared by both panels) routes the keyboard and mouse to whichever one shows the render. A second simultaneous view was not built.
- **Viewport:** F frames the selection (`focus_on`). Shows the scene through the ImGui texture registry; editor fly camera (right mouse + WASD); click picking (GPU ID buffer; a click on a gizmo handle wins); selection outline; Play/Pause/Step/Stop toolbar in the secondary bar; a Gizmos menu. The game UI is left out by default (`RenderModule::set_game_ui_visible`; the "Game UI" checkbox in its toolbar shows it, the Game panel always does).
- **Material:** materials.md. **Physics:** physics.md. **Input:** input.md. **UI Editor:** ui.md.
- **Build / Export:** the Export button in the main bar runs `pack_async` to `../game/` behind a blocking progress popup (disabled while a pack runs or during play).

## Gizmos (`editor/src/gizmo`)

Transform gizmo (translate/rotate/scale, W/E/R, world/local, Ctrl snapping, screen-constant size, axis and plane handles, hover highlight) writes the ECS transform directly. Passive gizmos: light shapes (directional arrow, point range sphere, spot cone), camera frustum, selection bounds, grid, axes, outline settings. Toggles persist in `gizmo_settings.json`. Hit-testing, rotation angle, snapping and ray/plane/axis closest-point are pure functions (no GPU, no ImGui) in `engine/src/math/gizmo_math.*`. Everything draws through `DebugDraw`.

## Play mode (`editor/src/play`)

`PlayMode` is a state machine `Edit / Playing / Paused` over an `IPlayHost` (so it is testable with a fake host); `EditorPlayHost` in `editor_module.cpp` is the real one.

- **Play** (only from Edit, only when `can_play()`: no scene opening, no prefab expansion pending): remember the edit scene and document (path, dirty flag, selection guid), `clone_scene`, show the clone as the active scene with `SceneEditor::set_playing(true)`, start the game clock and the scripts.
- **Pause/Resume** toggle the game clock. **Step** (only while paused) un-pauses for exactly one `update()` and re-pauses, running one frame of scripts with that frame's real `dt`.
- **Stop:** `stop_scripts()` first (so `on_destroy` runs while the play scene is still active), then stop the clock, then show the original edit scene and restore the document and selection; the clone is released. Closing the editor while playing stops first.
- If the active scene is replaced during play (a script's `load_scene`), the new scene becomes the play scene and scripts restart on it; Stop still returns to the original edit scene.
- Panels stay live while playing and can inspect/change the clone (changes vanish on Stop). Save/open/new are refused while playing (`set_playing`). Script errors never stop play.
- Physics worlds and the UI/input routing follow the same Play state (physics.md, input.md).

## Performance stats (`engine/src/core/perf_stats.*`, panel `performance_panel.*`)

`Engine::get_perf()` is a main-thread-only `PerfStats`: one `Series` (ring of 600 samples with current, average, max) per metric: main frame ms, per-module ms (`ModuleManager::run_phase` times every module call), render frame / render CPU (drained from the render snapshot by `RenderModule::render_update`), per-pass GPU ms, physics step ms and steps per frame (`PhysicsModule::pump_locked`), process RAM (`GetProcessMemoryInfo`) and VRAM used/budget (DXGI `QueryVideoMemoryInfo` on the adapter matched by the name the backend reports; works for Vulkan, D3D11, D3D12), both sampled four times a second in `system_memory.cpp`. Other threads publish plain data that main drains once per frame. The timers always run (no build-config macro); only the drawing is editor code, and the game can read the same stats.

The View Preview panel (Renderer menu, closed by default) shows a prefab in a `RenderView` of its own (views.md): orbit with the left mouse button, wheel to zoom, profile and transparent options, and Save PNG, which writes `Library/view_preview.png` through the readback path. The view exists only while the panel is visible. The Performance panel (replaced the old Renderer panel) shows a header (FPS, API, adapter, shader status, GPU errors), a per-thread table with sparklines (Main expands to per-module cost, Renderer to per-pass GPU), a ~10 s frame-time graph with 16.6/33.3 ms lines, hover readout and pause, RAM and VRAM graphs (VRAM amber above 85% of budget), and scene/cache/upload/physics counters. Graphs use `ImDrawList` polylines (ImPlot is not vendored). Missing data shows "unavailable", never a fake zero. Vsync lives in the World panel's Quality section. Optick is not integrated (only `vendor/Optick/Optick.exe` exists).

## Smoke flags

Each panel or system with a headless check runs through `editor_module.cpp`/its own `*_smoke_test.cpp`; the full table is in CLAUDE.md. A smoke check is trusted only after it was seen to fail under a negative control (break a line, confirm failure, restore). After editing a shader, run `wiwa_editor.exe --render-smoke 100 --api=d3d11` before `--render-test`.

## Animation panel (`editor/src/animation`)

Preview of a clip for the selected Animator (also in edit mode; dropped when the selection changes or Play starts), and the skeleton overlay. It no longer edits events: those are edited in the clip editor of the Asset Editor (below). Details: animation.md. Smoke: `--anim-smoke`, `--anim-panel-smoke`.

## Asset Editor (`editor/src/asset_editor`)

One panel for the animation assets: a preview on the left, the tools of the open asset on the right. Opened by a double click in the Asset Browser (`.wskel`, `.wmesh`, `.wanim`, `.wgraph`), by "Open in Asset Editor" in the Inspector's asset fields (skeleton and mesh) or the browser's context menu.

- **Preview** (`AssetPreview`): the skeleton posed in its own preview scene (a `RenderView`, Preview profile) with the skinned mesh that skins to it, or bones only. The mesh is the first skinned mesh that names the skeleton, or the one chosen with "Preview mesh" (saved in `Library/editor_state.json`). A clip dropdown (the clips that name the skeleton) plays with a time slider; a clip that fits only some joints says so. Bones, joint names and sockets are drawn over the image by ImGui from the pose, not by the debug renderer (that belongs to the main view). Orbit with the left button, zoom with the wheel.
- **Skeleton editor:** joint tree (double click or F2 renames; names are not empty, unique, at most 64 characters), sockets (add on the selected joint, rename, joint, position/rotation/scale, a translate/rotate/scale gizmo on the preview, W/E/R). Joints cannot be added, removed or reordered: meshes index joints by position. Renames update the sockets, and saving them first shows the list of `.wmesh` and `.wanim` files that name the joints; Apply rewrites those and then the skeleton (the skeleton last; if a write fails the others are put back).
- **Mesh editor:** vertex, triangle, slot and joint counts, the skeleton (drop another one to rebind: allowed only when it has every joint the skin names, the skin is remapped to its order; otherwise the missing names are listed) and a material picker per slot.
- **Clip editor** (`ClipEditor`, `ClipEditModel`, `DopeSheet`, `CurveView`): a `.wanim` opens with the preview playing the skeleton it names. The model (no ImGui) is snapshot undo (100 steps and about 64 MB), every call one step, drags one step, refused calls change nothing and set `error()`. The bottom pane has a dope sheet (ruler with the playhead, an event lane, a row per joint that opens into translation, rotation and scale rows; click or Shift/Ctrl or box selects keys, drag moves them with frame snapping, Alt-drag scales about the playhead, Ctrl+C/V/Delete, Ctrl+wheel zooms, middle button pans) and, under it, the selected joint's curves in `ImCurveEdit` (rotation as Euler degrees, stored as quaternions). Events: double click on the event lane adds, drag moves, F2 renames, Delete removes. Pose keying: the selected joint gets a gizmo on the preview (W/E/R); K or "Key pose" writes translation, rotation and scale at the playhead. The "Clip..." menu has Trim, Scale time, Set duration, Reverse, Resample, Reduce keys, Make additive and Rename; a dialog stays open and shows the model's error when the call is refused. **The preview plays the saved clip**: edits show there after Save (the importer cooks the file again), and the pose being dragged with the gizmo shows only as the gizmo.
- **Graph editor** (`GraphEditor`, `GraphEditModel`, `GraphCanvas`): a `.wgraph` opens (from the browser, or "New animation graph" in the Create menu: a base layer with one state that has no clip). The model (no ImGui) is snapshot undo like the others; every call is one step, a drag is one step, a refused call changes nothing and says why (renaming a parameter or a state rewrites everything that names it, deleting a used parameter lists where it is used, a layer keeps one state, the base layer stays). The tool pane has the skeleton slot, **Preview parameters**, parameters, layers (mode, weight or its parameter, mask root with falloff or joints), the states of the selected layer (clip slot or blend-space samples with axes, speed, loop, make default, delete), and the transitions (from, to, order, crossfade, exit time, conditions). The bottom pane has a tab per layer and the node canvas (the vendored `GraphEditor` widget): states as nodes (the one playing in the preview is marked), Entry (drag from it to a state: the default state), Any state, links as transitions; drag nodes (one step), drag from a node's output slot to a state to add a transition, pick a link up to delete it, right click: add state here, make default, delete state. **The preview plays the saved graph**: edits show after Save, and Save refuses a graph that breaks `graph_valid` (it says why and writes nothing). Preview parameters are live controls on the preview's instance (sliders, checkboxes, a Fire button per trigger, and the state of each layer); the values are put back when the graph is cooked again. Smoke: `--anim-panel-smoke`.
- **Panel:** Undo/Redo (Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z while it is focused; drags are one step), Save (Ctrl+S, which then does not save the scene), `*` in the title while unsaved, Save/Discard/Cancel when switching asset or closing, an "external change" bar when the file changed on disk while there are unsaved edits (an unmodified editor reloads at once).
- **Thumbnails** (`ThumbnailCache`, `Library/thumbnails/<guid>-<key>.png`, `VERSION` bump remakes all): `.wskel`/`.wanim`/`.wmesh` are posed by the animation module; `.wmat` is the engine's own sphere (`assets/builtin_assets.h`, held in the render thread's `GpuResourceCache` under a fixed reference, so no project asset is needed) and `.wprefab`, `.glb`, `.gltf` and `.fbx` are the prefab (a model file imports as one; `PreviewModel`, framed by its bounds), all drawn by the shared view and waiting `STATIC_SETTLE_FRAMES` for textures and meshes to reach the GPU. The scene is `make_preview_scene` (key, fill and rim directional lights, no shadows in this profile) with the ambient at 1.0. A GPU thumbnail whose picture touches the border is taken again from farther away (up to `MAX_ZOOMS` times), so the whole asset is in view; `.hdr` (a tonemapped lat-long strip of cube mip 0), `.cube` (a hue sweep and gray ramp put through the table) and `.ttf`/`.otf` ("Aa" from the SDF atlas) are made on the CPU from the cooked data, no view. Their keys: `.wmat` hashes the file and the textures and shader it names, `.wprefab` its own file only (a changed mesh inside does not remake it), the big source files by size and time. Not covered: surface shaders (no material to show them on), scenes, UI panels, physics shapes (opaque Jolt data), and the types with nothing to see (scripts, shaders, input maps, physics materials, graphs). `handles()` is every file with a thumbnail, `is_animation_asset()` the three the Asset Editor opens.
- **Import settings** (`ImportSettingsModel` without ImGui in `asset_pipeline`, `ImportSettingsDialog` in `panels`): the Asset Browser's context menu has "Import settings..." (only for files whose importer is `editable()`), "Reimport" (any importable file, forced), "Reimport folder" (a selected folder) and "Reimport this folder". The modal is drawn from the importer's schema: a marker and a "reset" button on options that differ from their default, Apply (disabled until something changed; stores the values and starts the reimport, the dialog closes), Revert, Defaults, Cancel. Entries of the `.meta` that are missing, mistyped or out of range are fixed on open and listed. Reimporting runs on the worker pool; `EditorModule::reimport_modal` shows a bar like the export's (done/total and the file, Cancel), and lists the files that failed when it ends (it closes by itself when all went well). A right click selects the file, so the menu is about the file under the cursor. Files dragged onto the editor window from the OS (`Window::take_dropped_files`, a GLFW drop callback) are copied into the open folder (never over a file: `name (n).ext`), imported with the defaults (in the background) and, if editable, queued for the dialog once that import is done, one after the other; Cancel keeps the default import. Files the watcher or a scan finds never open the dialog. Drawn by `EditorModule` every frame, so it works with the Asset Browser closed.
- **Asset Browser:** the three animation file types have their own icons and thumbnails, a tooltip with a summary and the model they were extracted from, and "Re-extract from model..." which makes the model forget that file and imports it again, so a fresh copy appears next to the old one (nothing is overwritten).

## Editing services (`editor/src/editor_ui`, `editor/src/scene`)

- **Undo and redo** (`scene/undo_stack.*`, `SceneEditor`): whole-document snapshots (compact JSON from `scene_to_json`). Every mutator ends in `mark_dirty(label)`; `SceneEditor::update()` turns a settled change into one step (the previous snapshot, the label of the first change), so the edits of one frame, or of anything held, are one step: `EditorModule::update` opens an edit scope while any widget is active or the transform gizmo is in use and closes it on release (the gizmo and sliders change the scene every frame of a drag). Undo is not available while a scope is open. Capped at 100 steps and 64 MB. Not available while playing, opening a scene or expanding a prefab instance (`can_edit_history()`); cleared on a new or opened scene, kept across Play and Stop (play mode shows a copy; the history belongs to the scene being edited); undoing back to the saved snapshot clears the dirty flag. Restores destroy the roots and apply the snapshot, then queue prefab instances for expansion (the selection or Inspector lock on a generated node is lost until the nodes exist). Saving records the snapshot of that moment as the saved state, so the dirty flag stays right. The UI Editor keeps its own undo (its window is skipped by Ctrl+Z); the Animation panel has none. Edit menu (names the step), History panel (click to jump).
- **Shortcuts** (`shortcuts.*`): one table (`ShortcutRegistry`) for the menus, the F1 cheatsheet and the command palette; nothing fires while a text field takes input. Ctrl+Z/Y/Shift+Z, Ctrl+S, Ctrl+D, F2, Ctrl+C/X/V, F, Shift+Space (maximize), F11 (UI Editor), Ctrl+P, F1.
- **Entity templates** (`scene/entity_templates.*`): Empty, 3D (Cube, Sphere, Cylinder, Cone, Torus, Plane from `Assets/models/shapes/shapes.glb` mesh local ids 1-6, listed only while that model is in the catalog; the engine has no built-in primitive meshes and no capsule mesh), Physics (Rigidbody Cube/Sphere, Character controller), Light (directional, point, spot), Camera, UI Canvas, Animator.
- **Clipboard:** `SceneEditor::copy_entity` / `paste_entity` keep the authored subtree as records (fresh guids on paste, prefab instances expand again); the clipboard outlives the scene.
- **Layouts** (`layout_manager.*`): built-in presets (Default, Level Design, Animation, UI Editing, Debug) built with `DockBuilder` over the panel names (the UI Editor by `###UiEditor`); a preset opens the panels it lists and closes the other panels of the menus. User layouts are ImGui ini text in `layouts/<name>.ini` (Window > Layouts: Save current layout, load, delete, Reset). The first run (no `imgui.ini`) applies Default; `imgui.ini` otherwise keeps the last layout. Panel open flags are saved in the same ini text by an ImGui settings handler (`[PanelState][Panels]`, `<window name>=0|1`, panels outside the menus are skipped; a missing entry keeps the default), so the editor opens with the panels it was left with and a saved layout restores its panel set. **Start maximized** (Settings > Editor, `startMaximized` in `gizmo_settings.json`, default on): the editor reads it before the window exists and asks `Engine::set_start_maximized`; `Window::init` maximizes only a non-project (editor) window, and command-line runs (any `--` argument) keep the plain window. Applied in `dock_space()` before `ImGui::DockSpace`.
- **Maximize** (`LayoutManager::toggle_maximize`): Shift+Space on the panel under the mouse, Window > Maximize panel, the UI Editor's button or F11. The panel is undocked and floated over the dock area each frame, the other panels are not drawn, Esc (not while playing or with the palette open) or closing restores: the whole layout comes back from the ini text taken when it was maximized, because the panel's old dock node is deleted when it was alone in it. The maximize, palette, cheatsheet and F11 shortcuts do not fire while playing. The maximized Game or Viewport owns the render view because no other view panel is drawn.
- **Command palette** (`command_palette.*`, Ctrl+P): actions, panels, layouts, entities of the scene and assets of the catalog, fuzzy subsequence ranking; the editor collects the items on open.
- **Find references** (`asset_pipeline/reference_finder.*`): a worker thread (`std::async`) reads `.wscene`, `.wprefab`, `.wmat`, `.wuipanel`, `.winput`, `.wphysmat` under the source roots and counts the asset's guid string (materials name textures and shaders by relative path, so `.wmat` files are also searched for the asset's file name); the References window lists files (click locates, double-click opens a scene or UI panel). From the Asset Browser and the asset slot menus. Read only.
- **Status bar and recents:** a bottom bar (`BeginViewportSideBar`: scene and dirty mark, selection, undo steps, FPS); File > Open Recent (up to 8, `recent_scenes.txt` next to the editor).
- **UI Editor:** draggable splitters between the three columns, mouse wheel zoom (0.1 to 4) and middle-drag pan over the canvas, Fit, tree search, Revert (asks first), Maximize button.
