# Animation Foundation Design (animation, part 1 of 5)

> Historical design record, written before the area was built. Its status line may be out of date. What exists now is described in animation.md; where the two differ, that doc is right.

Date: 2026-11-04. Status: draft, awaiting review.

## Where this fits

Animation is built in five parts, each with its own spec, plan and implementation:

1. **Foundation (this spec):** GPU skinning, `Animator`, clip playback, crossfade, additive layers, events, Lua API, editor preview.
2. **Animation graph:** parameters, state machines, blend trees, layers and masks, transitions, editor graph panel (ImGuizmo's `GraphEditor`, vendored then).
3. **Root motion:** extracted from clips, fed to the character through physics.
4. **IK:** two-bone, look-at, foot IK (ground from physics raycasts).
5. **Ragdoll and physical animation:** Jolt `Ragdoll` and `SkeletonMapper` over our pose arrays.

Parts 2 to 5 are not built here. This spec only keeps them possible (see "Hooks for later parts").

## Decisions (from brainstorming)

- Authoring is both: a graph is the main path later, and Lua can play or blend a clip directly now (`anim:play`, `crossfade`, `layer`).
- The `Animator` owns a flat pose buffer. Joint entities are not the truth; only `AnimationSocket` entities are written back.
- Scale target: a handful of animated characters (up to about 20), main-thread evaluation, vertex-shader matrix palette. The design keeps a later move to job evaluation and compute skinning open, and builds none of it.
- Clip features: loop and once, speed, crossfade, additive layers, joint masks, events on clip time. No retargeting, no morph target rendering.
- One evaluation model for Lua and (later) graphs: a small tree of pose nodes.
- Jolt is not used by the foundation (its `SkeletalAnimation` has no events, layers or additive playback). It enters in part 5.

## Assets

`Skeleton` and `AnimationClip` stay the asset types. `SkeletonData` gains what blending, additive layers and IK need:

- joint names;
- parent joint index per joint (the hierarchy is only in the Prefab today); the importer orders joints so a parent always comes before its children;
- rest pose per joint (local translation, rotation, scale).

The importer warns above 256 joints per skeleton (the palette cap). The cooked format changes, so the asset version is bumped and `Library/` re-imports.

`AnimationClipData` gains `Events` (`{time, name}`), merged at import from the model's `.meta`. Editing an event re-imports the model.

A **ClipBinding** maps each clip channel (keyed by Prefab node index) to a joint index of a skeleton, by joint node. It is built when a clip first plays on a skeleton and cached per (clip, skeleton). Channels for nodes outside the skeleton are ignored with one warning per clip.

## Components

Both use `WI_COMPONENT`/`WI_FIELD`, so serialization, inspector and prefab overrides work unchanged. They hold `AssetRef`, never `Handle<T>`.

- `Animator` (on the model's root entity): `Skeleton`, `Clips` (AssetRefs, filled from the model's animations when the prefab instance is created; clip names are unique per model), `Clip` (default, played on start), `PlayOnStart`, `Speed`, `Enabled`, `BoundsPadding`, and a reserved `Graph` (part 2).
- `AnimationSocket` (on any descendant entity): `Joint` (name), `Offset` (position and rotation). After evaluation the module writes that entity's `Transform` from the pose.
- `SkinBinding` (on a skinned mesh node, generated by the prefab expander from the node's skeleton reference): `Skeleton`. The module finds the owning `Animator` by walking up the `Hierarchy` to the nearest ancestor `Animator` with the same skeleton.

Runtime state (node tree, pose buffers, previous palette, event cursors) is not a component. `AnimationModule` keeps one `AnimatorInstance` per `Animator`, like `UiModule` keeps `UiPanelInstance`. A scene clone for Play mode starts with fresh instances; Stop discards them.

## Evaluation

`Pose` is a flat array of local joint transforms (translation, rotation, scale) indexed by joint. Model-space matrices come from one forward pass (parents come first). The palette is `model[j] * inverseBind[j]`.

Every pose node has two functions:

- `advance(dt, events)` moves time and state and may emit clip events. It touches only that node.
- `evaluate(out)` writes a pose and is a pure function of the node's own state.

Nodes:

| Node | Does |
| --- | --- |
| `Clip` | time, speed, loop or once, a ClipBinding; samples with a per-channel keyframe cursor |
| `Blend` | two inputs and a weight: lerp translation and scale, nlerp rotation along the shortest path |
| `Additive` | base, additive input, weight; the additive input is a clip pose relative to a reference frame (the clip's first frame by default) |
| `Mask` | per-joint weights (a joint and its subtree), limits a layer to part of the body |

Lua-driven play builds and edits a tiny tree:

- `play(clip)` replaces the root with a `Clip` node.
- `crossfade(clip, seconds)` wraps the current root as `Blend(old, new, w)` and ramps `w`; at `w == 1` the old subtree is dropped. A crossfade started during another one nests, and any node whose weight has fully faded out is dropped, so the tree stays bounded.
- `layer(name, clip, {mask, weight, additive, loop})` adds a named layer above the base from the same node types, with the same collapse rules.
- A clip that has not loaded yet is held and starts the frame it is Ready.

Events: `advance` emits every event whose time lies inside the interval just played, including across a loop wrap. An event fires only if its clip's effective weight in the tree is above 0.5, so both sides of a crossfade do not fire a footstep.

### Update order

`AnimationModule` has priority 10 (after scripts at 0, so evaluation sees the state scripts set this frame). Per frame:

1. at the start of the scripts' update, queued events of the previous frame are delivered (handlers registered with `anim:on`), before `on_update`;
2. scripts run;
3. `AnimationModule::update`: advance, evaluate, build palettes, write sockets, queue events;
4. `pre_render_update`: palettes go into the render snapshot.

Events therefore reach scripts one frame late, the same latency as UI events. `joint_world` reads the previous frame's pose for the same reason; a socket entity follows exactly.

## Skinning and rendering

- A primitive with `Skinned` set gets its joints and weights uploaded to a separate structured buffer by the render-side mesh cache (`GpuResourceCache`), inside the existing upload budget. Shaders pull skin data by vertex index, so the vertex layout and the pipelines do not change and rigid meshes are unaffected. The branch is on a per-instance value, so it is uniform.
- Each frame the snapshot carries, for every skinned instance, its palette (`float4x3` per joint) and the previous frame's palette. The main thread keeps the previous one (the render thread holds no per-character history), the same way `PrevWorld` already travels in `SceneInstance`. `SceneInstance` gains a `PaletteOffset` (`~0u` for a rigid mesh). The render thread copies the palette arrays into one per-frame structured buffer; it is a few KB per character, so it bypasses the upload byte budget.
- `scene_common.hlsli` gets `SkinPoint` and `SkinNormal`. Every vertex path that reads a mesh uses them before the world matrix: depth, depth-mask, shadow, forward, pick, selection outline and the `surface_*` shaders. `PreviousClipPosition` skins with the previous palette, so TAA and motion blur include the animation.
- A user surface shader's `VertexOffset` is applied in object space before skinning (one line added to the surface contract doc).
- Normals use the palette's upper 3x3: non-uniform joint scale is not supported (documented).
- Frustum culling uses the mesh's static bounds inflated by `Animator::BoundsPadding`.
- Seam for later: the render thread only knows "this instance's palette starts at N". A compute pre-skin pass can replace the vertex-shader path without changing the snapshot.

## Lua API

`bind_animation.cpp`, documented in `docs/scripting.md`.

```lua
local anim = Animation.animator(self.entity)        -- nil if the entity has no Animator
anim:play("Idle", { loop = true, speed = 1.0 })
anim:crossfade("Run", 0.2, { loop = true })
anim:stop(0.3)
local up = anim:layer("upper", "Wave", { mask = "Spine", weight = 1.0, additive = false, loop = false })
up.weight = 0.5; up:crossfade("Aim", 0.1); up:stop(0.2)
anim:on("footstep", function(self, event) end)      -- event = { name, clip, time }
anim:off("footstep")
anim.speed, anim.time, anim.playing, anim.ready
local m = anim:joint_world("RightHand")             -- mat4, last evaluated pose
```

- A clip is a name in the `Animator`'s `Clips` or an asset from `load_asset`. An unknown name is an error that lists the available clips.
- Handles to a destroyed entity (animator) or a stopped layer read `nil` and ignore writes, like UI widget handles.
- Handlers belong to the script instance and go away with it. A handler that raises an error is logged and removed.
- No per-joint pose writing from Lua (procedural poses are IK, part 4). Graph parameters (`anim:set`) arrive in part 2.

## Editor

All in `editor/src/animation` (the game never links it).

- `AnimationEditModel`: ImGui-free document with undo for clip events, like `UiEditModel` and `InputEditModel`.
- `AnimationPanel`: for the selected entity with an `Animator`, preview of a clip (play, pause, scrub, speed, loop) in the viewport, including in edit mode, and a timeline to add, drag, rename and delete events. Preview drives the `AnimatorInstance` directly, is never saved, and is dropped when the selection changes or Play starts. The timeline is plain ImGui.
- The inspector shows `Animator` and `AnimationSocket` through reflection; the socket joint is a drop-down of the skeleton's joints. A skeleton overlay (toggle) draws the joints through `DebugDraw`.

## Checks

No test framework; smoke commands, each trusted only after a negative control.

- `--anim-smoke` (editor): import round trip (parents, rest pose, events, joint cap warning); sampling of step, linear and cubic channels against known values; blend, additive and mask math; crossfade collapse including a crossfade started during another; events across a loop wrap and the 0.5 weight threshold during a crossfade; rest-pose palette equals identity; Lua API (`play`, `crossfade`, `layer`, `on`, handle invalidation, unknown clip error); evaluation determinism; fresh instances after a scene clone.
- `--anim-panel-smoke` (editor): draws the panel for 130 frames with ImGui asserts on, edits an event through it and checks it was saved.
- `--render-test`: a skinned quad with a known palette matches the expected pixels; a second check does the same for the velocity target with a moving palette (negative control: a zeroed previous palette must change the result).

## Demo, docs, conventions

- `demo.wscene` gets a `gotg` character that has usable clips (chosen when writing the plan) with an `Animator`, a Lua script that crossfades idle and run from the input actions, a footstep event and an `AnimationSocket` prop.
- Docs: an "Animation" section in `docs/scripting.md`; an Animation paragraph in `CLAUDE.md`; the Lua completion stubs written by the editor.
- This spec is not committed (project rule).
- `AnimationModule` (engine lib) is registered in `Engine` like the other modules; importers and the panel stay in the editor. Logging uses `WI_LOG` variants (`WI_ANIM_LOG`).

## Hooks for later parts

- Part 2: the `Graph` field, a state-machine pose node, `anim:set`. The graph compiles to the same node types.
- Part 3: `Pose` gains a root delta; `advance` accumulates it per frame.
- Part 4: IK nodes run after the output node on the pose (two-bone, look-at, foot); foot IK reads physics raycasts, so it needs the physics snapshot of the same frame. If evaluation moves to jobs, IK stays on the main thread after the join.
- Part 5: our flat `Pose` arrays convert to `JPH::SkeletonPose` for `SkeletonMapper` and `Ragdoll`.
- Job evaluation: `evaluate` is pure and writes only the Animator's own buffers, so it can be dispatched per character; a sync point goes before the snapshot is built.

## Out of scope

Retargeting, morph target rendering, animation LOD, job evaluation, compute skinning, non-uniform joint scale, per-frame pose-derived bounds, procedural pose writes from Lua, graph, root motion, IK, ragdoll.
